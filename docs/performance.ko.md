## 유휴·트레이 동작 — 2026-10-08

Windows x64·논리 프로세서 16개에서 실제 화면 번들, Electron 41.10.7·내장 Node.js 24.18.0으로 비교했습니다. 이전 기준은 `5ba36f0`입니다. 상태별 2초 준비 후 15초를 측정했습니다. 두 버전 모두 빈 새 프로필이며 실제 방송·AI 구성요소·개인 인증 정보·강제 GC를 사용하지 않았습니다. AI 상태는 설정 → AI 화면을 연 뒤 트레이로 숨겨 비교했습니다. 실제 창 검사와 측정은 순차 실행했습니다.

| 상태 | CPU 이전 → 개선 후 | 메모리 이전 → 개선 후 |
| --- | ---: | ---: |
| 홈 표시 | 0.141% → 0.188% | 227.9 → 220.0 MiB |
| 홈 최소화 | 0.045% → 0.043% | 227.8 → 218.7 MiB |
| 홈 트레이 | 0.038% → 0.036% | 228.5 → 214.9 MiB |
| AI 설정 표시 | 0.199% → 0.131% | 229.2 → 228.2 MiB |
| AI 설정 트레이 | 0.118% → 0.028% | 222.2 → 219.9 MiB |

CPU는 앱 프로세스들의 누적 CPU 시간 차이를 합쳐 논리 프로세서 수로 나눈 값입니다. 메모리는 앱 프로세스의 private bytes 합계를 MiB로 표시합니다. working set 합계는 공유 페이지를 중복 계산할 수 있습니다. 짧은 유휴 CPU 측정은 변동이 있으며 이번 표시 상태의 CPU는 JavaScript 작업 감소에도 증가했습니다. 모든 PC의 보장 값이나 방송 연결 상태의 측정은 아닙니다.

이전 버전은 상태마다 엔진 스냅샷을 15회 만들었으며 숨김·최소화에서도 생성했습니다. AI 상태에서는 조회도 각각 10회 발생했습니다. 개선 후 빈 프로필의 측정 구간에서는 두 작업 모두 발생하지 않았습니다. AI를 추가했다면 표시 중인 설정은 10초 상태 조회를 유지하고 트레이에서는 해당 UI 조회를 중단합니다.

최초 JavaScript는 **427.53 → 334.45kB(21.8% 감소)**, 최초 CSS는 **128.76 → 79.42kB(38.3% 감소)**입니다. 타임라인·AI 번들은 패키지에 모두 포함하고 필요할 때 로드합니다. 기능을 제거한 결과가 아니며 설치 파일도 같은 비율로 줄었다는 의미는 아닙니다.

백그라운드 검사는 실제 수집 콜백과 로컬 네트워크 대체물을 사용해 **채팅 2,001건·후원 10건**, 중복 제외·정확한 저장 순서·실제 Windows 전역 마커 단축키·투표 자동 마감·숨긴 화면의 스냅샷 미생성·표시/복귀 시 최신 상태를 확인합니다. 수집·연결 유지와 재접속·방송 감지는 앱에서 계속 수행합니다. 기록 중 1초 저장과 메타데이터 5초 저장 주기를 유지하고 연속 채팅에서 저장 시점 유지와 실패 재시도도 단위 검사합니다. AI 인증·분석 작업은 앱에서 진행하며 트레이 최적화는 UI 작업을 줄입니다.

## 합성 기록 측정

24일·채팅 24,000건의 암호화 파일은 **741,456 → 566,024바이트(23.7% 감소)**였습니다. 첫 날짜 조회는 **91개 → 1개** 청크를 읽었고 5회 중앙값은 **80.81 → 0.90ms**였습니다.

저속 기록 예시에서 1초 저장 120회를 수행한 결과 **120개 파일·46,268바이트 → 1개·2,032바이트**였습니다. 1초 저장 주기를 유지하고 같은 날짜의 제한된 마지막 파일을 원자적으로 합칩니다.

AES-GCM 테스트 저장소를 사용하므로 Windows DPAPI 실제 시간과는 다릅니다. 디스크·운영체제 캐시·채팅 패턴·기록 크기에 따라 결과가 달라집니다. 개인 프로필이나 실제 채팅을 측정하지 않았습니다.

## 재현

- `npm run benchmark:timeline`은 임시 합성 데이터를 만들고 정리합니다. 새 체크아웃은 현재 결과를 출력하며 이전 비교에는 로컬로 보관한 이전 코드가 필요합니다.
- `npm run benchmark:idle`은 검증된 화면을 빌드하고 빈 임시 프로필을 측정합니다. `node scripts/benchmark-idle.cjs --sample-ms 15000 --output release/idle-performance-optimized.json`으로 위 측정 구간을 재현합니다. `--root <이전 체크아웃>`은 별도로 빌드한 이전 버전을 동일한 도구로 측정합니다. 보고서는 CPU·private memory 합계, 화면 힙·스크립트 시간, 스냅샷·IPC 횟수를 담고 개발 프로필은 사용하지 않습니다. 로컬 비교 파일은 `release/idle-performance-baseline.json`·`release/idle-performance-optimized.json`입니다.
- `npm run build`는 `release/renderer-build-timings.json`을 기록합니다. 새 번들은 `node scripts/build.cjs --force`, 증분 타입 상태 초기화는 `.build-cache/typescript.tsbuildinfo`만 제거합니다.
- `npm run test:desktop`은 `release/desktop-test-results.json`에 검사별 시간을 남깁니다. 선택 실행은 별도 보고서를 사용합니다.
- `npm run dist:all`은 `release/build-timings.json`을 기록합니다. 겹쳐 실행되는 단계 시간을 더한 값은 전체 시간과 다릅니다.
- 로컬 비교 보고서는 `release/build-performance-report.json`·`release/test-performance-report.json`입니다. 생성 결과는 Git에서 제외합니다.

캐시 검사는 수정 시각을 유지한 편집, 결과 변조·누락, 환경·가져온 파일 변화와 네이티브 의존성 추가를 확인합니다. 실제 TypeScript 오류를 넣어 게시 실패·이전 결과 보존·오래된 소스의 패키징 차단도 확인했습니다.
