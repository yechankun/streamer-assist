# 방송 기록과 채팅 분석 데이터

[English](timeline-data.md)

## 방송 기록·다시보기 수집 방식

**설정 → 방송 기록**에서 다음 방송의 방식을 선택합니다. 진행 중인 방송은 시작할 때 선택한 방식을 유지합니다.

| 방식 | 방송 중 | 방송 종료 후 |
| --- | --- | --- |
| 실시간 저장·분석 | 채팅·후원 원본, 실시간 기능, 시청자 수·마커를 기록합니다. 반응 집계는 증분 처리하고 상세 통계는 별도 워커에서 요청 시 계산합니다. | 저장한 기록을 조회·분석합니다. |
| 실시간 원본 저장·종료 후 분석 | 원본·기본 집계를 유지하고 전체 통계·반응 분석은 미룹니다. | 수동 또는 설정한 자동 통계·하이라이트 계산을 실행합니다. |
| 실시간 기능만·종료 후 다시보기 수집 | 투표·추첨·도네 투표·룰렛·마커·시청자 수는 유지합니다. 채팅·후원 원문은 실시간 기록과 수신 저널에 저장하지 않습니다. 기능의 참여 상태·결과는 저장될 수 있습니다. | 타임라인의 **다시보기 수집**에서 방송 영상을 찾거나 URL을 여러 개 추가하고, 채팅을 가져와 선택적으로 분석합니다. |

하나라도 방송이 시작되면 자동 기록하고 모든 방송이 확인된 종료 상태일 때 종료합니다. 같은 채널의 재시작도 방송 ID별로 보존하며 자정을 넘긴 방송을 날짜 하나로 잘라 처리하지 않습니다. 다시보기 채팅을 가져와도 기존 투표 결과·당첨자·수동 마커·시청자 수 기록은 유지하며 가져온 메시지가 실시간 투표·모집에 참여하지 않습니다.

YouTube는 선택 다운로드한 [yt-dlp](https://github.com/yt-dlp/yt-dlp)의 `live_chat` 트랙, Twitch는 [TwitchDownloaderCLI](https://github.com/lay295/TwitchDownloader)의 VOD JSON을 사용합니다. 공식 GitHub 릴리스의 고정 버전·SHA-256을 확인하고 앱 전용 경로에 설치하며 설치 프로그램에는 포함하지 않습니다. 치지직은 웹 플레이어의 페이지형 내부 API를 사용합니다. 전체 전달이 공식 보장되는 경로가 아니며 [참고 구현도 페이지 중복·누락 검증의 한계](https://github.com/dudska12/chzzk-chat-report/blob/main/src/vod-chat.ts)를 명시합니다.

가져오기는 영상별로 진행하고 응답·파일을 조금씩 처리하며, 저장 완료 뒤 마지막 가져오기 위치를 보관합니다. 중지·재시도는 저장한 위치를 유지합니다. 외부 도구 방식은 재시도 시 파일을 다시 다운로드할 수 있습니다. 외부 도구가 만드는 작업 파일은 다운로드 중 암호화되지 않을 수 있으며 앱의 개인 작업 폴더에만 두고 완료·중지·실패 시 삭제합니다. 최종 채팅과 작업 상태는 암호화합니다.

원본 이벤트에는 `origin: vod-replay`, 영상 ID·원본 시각·VOD 위치를 보존합니다. **다시보기에 제공된 채팅**이며 방송 당시 전송된 모든 메시지를 보장하는 기록은 아닙니다. 삭제·비공개·접근 불가 영상, 없는 채팅 트랙, 운영·관리 조치와 내부 API 변경에 따라 수집할 수 없을 수 있습니다. 잘린 영상이나 시각 정보가 부족한 영상은 시작 시각을 조정해야 합니다. 다시보기로 실시간 시청자 수나 당시 투표·추첨 결과를 복원하지 않습니다.

## 고부하와 장애 복구

최근 10,000건을 메시지마다 반복 순회하던 처리를 10초·70초 증분 집계로 바꿨습니다. 화면 전달은 합치고 수신 처리는 짧게 나눠 메인 스레드의 조작·단축키·마감 처리를 유지합니다. 원본 저장 모드에서 큰 적체는 암호화된 수신 저널로 넘기며 실시간 기능만 사용하는 모드에서는 이 원문 저널을 만들지 않습니다.

원본 압축·암호화·쓰기와 상세 분석은 별도 워커에서 처리합니다. 원본 기록은 AES-256-GCM을 사용하고 프로필 키는 Windows DPAPI로 보호합니다. 참여자 SQLite의 이름·고유 정보는 암호화한 데이터이며 색인에는 설치별 익명 키·집계·플랫폼을 사용합니다. 이전 DPAPI·Base64 형식은 같은 Windows 프로필에서 사용 시 변환합니다.

소유한 대기 패킷은 원본·메시지 ID 색인의 저장 완료 응답까지 유지합니다. 디스크 실패는 재시도하고 워커 종료 시 확인되지 않은 패킷을 재처리합니다. 참여자 분석 50,000명·추첨 10,000명·도네 이벤트 50,000건에서 멈추던 제한을 제거하고 메모리 조회 캐시는 제한합니다. 방송 종료·앱 종료는 수신 작업을 비운 뒤 기록을 마무리합니다. 프로세스·OS·전원이 갑자기 종료되면 영속 수용 전 메모리 구간의 메시지를 잃을 수 있으며 무기한 저장 장애·지속적인 처리 용량 초과의 무손실은 보장하지 않습니다.

YouTube는 공식 [스트리밍 RPC](https://developers.google.com/youtube/v3/live/streaming-live-chat)와 처리 완료한 페이지 토큰을 사용하고 재시도하는 폴링을 대체 경로로 둡니다. Twitch는 일반 연결 공백에 [이벤트 재전송을 제공하지 않습니다](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/). 치지직의 공개 소켓·다시보기 내부 API도 전체 메시지 전달을 보장하는 근거가 없습니다. 앱의 복구 범위와 플랫폼 전달 범위를 구분합니다.

`node scripts/benchmark-chat-load.cjs --rate 20000 --seconds 30 --mode live`는 독립 JSON 송신자, 실제 앱 화면 갱신·투표·추첨·Windows 암호화 저장을 포함한 빈 임시 프로필 측정입니다. 10,000·20,000·50,000건/초와 `live,deferred,replay`를 지원합니다. 실제 송신 속도·수신/저장 건수·대기량·종료 후 처리 시간·누락·메모리·이벤트 루프 지연을 기록합니다. 짧은 유한 실험은 무기한 처리량 보장이 아니며 실제 플랫폼 전달은 제외합니다.

새 운영 저장기는 1초 저장을 유지하고 청크를 최대 20,000개 이벤트·8MiB로 제한합니다. 기존 동기 저장기·테스트 형식은 256건·128KiB를 유지합니다. 선택 날짜의 용량은 암호화한 원본 청크 기준이며 공통 파생 색인·SQLite 크기는 제외합니다.

연결된 치지직·YouTube·트위치 채널을 주기적으로 확인합니다. 자동 감지를 켜면 하나라도 실제 방송이 시작됐을 때 기록을 시작하고, 모든 연결 채널의 종료가 확인되면 기록을 저장하고 끝냅니다. 네트워크·인증 오류는 종료와 구분합니다. 직접 기록 종료를 누르면 같은 방송은 재시작하지 않으며, 방송이 끝나거나 자동 감지를 다시 켜면 다음 기록을 시작할 수 있습니다.

처음 감지할 때 확인된 방송 시작 시각 중 가장 이른 시각을 공통 시간축으로 사용합니다. 플랫폼 시작 시각이 없으면 감지 시각을 사용합니다. 실제 수집은 앱이 기록을 시작한 시점부터이므로 이전의 누락 채팅을 복원했다고 표시하지 않습니다. YouTube가 접속 시 제공한 과거 채팅은 별도 표시해 보관하고 투표·반응 급증 판정에는 포함하지 않습니다.

## 저장 구조

방송 제목·마커·통계·시청자 분석용 비밀값은 기존 암호화 기록에 보관합니다. 원본 채팅·후원·시청자 수는 timeline-data/<방송 UUID>/에 압축한 원본은 DPAPI로 보호한 프로필 키와 AES-256-GCM으로 암호화해 묶음 파일·통계 색인에 저장합니다. 묶음은 원자적으로 쓰고, 복구할 때 색인보다 새로운 이벤트 시퀀스를 다시 읽으며 마지막 파일에 추가된 이벤트도 포함합니다. 기록은 직접 삭제할 때까지 보관하며 내보낸 파일은 사용자가 관리합니다.

| 이벤트    | 기록 정보                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------- |
| 시청자    | 플랫폼별 안정적인 분석 ID, 공개 플랫폼 ID, 닉네임과 관측 시각, 구독 여부·공개 역할·배지                  |
| 채팅      | 원문, 작성자 분석 ID, 플랫폼·메시지 ID, 실제 발생 시각·수신 시각, 과거 메시지 여부와 당시 역할·구독 정보 |
| 후원      | 채팅 정보와 후원 금액·통화/단위·종류. 익명 후원은 실제 시청자 ID에 연결하지 않음                         |
| 시청자 수 | 표본 시각·플랫폼별 실제 동접·조회 가능 여부·방송 상태. 조회 불가 값은 null                               |

분석용 시청자 ID는 이 설치의 비밀값과 플랫폼·계정 ID로 생성합니다. 같은 플랫폼의 같은 계정은 방송이 바뀌어도 연결할 수 있고, 다른 플랫폼의 같은 닉네임은 합치지 않습니다. 기록을 모두 삭제하면 분석 ID도 새로 생성됩니다. 구독·역할·배지는 플랫폼이 실제로 제공한 정보만 사용합니다.

## 조회·분석

시간 구간·플랫폼·채팅/후원·내용·시청자별로 기록을 조회합니다. 분 단위 채팅량, 시점별 정량 요약, 웃음·질문·감탄·링크 반응, 자주 사용한 표현과 반복 문구, 참여자별 기록·닉네임 변경을 분석할 수 있습니다. 통화나 Bits 같은 단위는 섞어서 환산하지 않습니다. 반응 분석은 로컬 문구·통계 계산이며 AI 감정 판정이나 영상 판독 결과가 아닙니다.

화면에는 요약과 필요한 기록 구간만 읽습니다. 채팅 목록은 최신 기록부터 시작해 아래로 스크롤할 때 이전 기록을 100건씩 이어 읽으며, 화면 주변의 행만 렌더링합니다. 발생 시각·방송 UUID·이벤트 시퀀스를 기준으로 이어 읽기 커서를 사용해 중복을 제외합니다. 실시간 새 기록은 목록 맨 위에서 갱신하고 이전 기록을 읽는 동안에는 위치를 유지합니다. 표시 색인의 크기가 제한돼도 원본은 보관합니다. 저장 실패와 수집 누락은 별도로 표시합니다. 시청자 그래프는 실제 플랫폼 동접이며 채팅 작성자 수로 추정하지 않습니다.

## CLI/API AI 연결용 형식

UTF-8 JSONL을 비동기 스트림으로 내보냅니다. [선택적 AI 연결](ai-integrations.ko.md)은 같은 시점·화자 정보를 제한된 컨텍스트로 구성해 사용자가 실행할 때 선택한 CLI/API에 전달합니다. 전체 범위의 건수와 포함된 샘플 수를 구분합니다. 내보내기 형식은 다음과 같습니다.

1. manifest: 형식·버전, 방송/수집 시각, 시간축, 연결 소스와 가명 처리 방식
2. 시청자·채팅·후원·동접 이벤트: 실제 UTC 시각, 밀리초 경과 시점, 동일 시청자를 연결하는 키
3. markers: 편집 후보와 로컬 통계 근거
4. summary: 분 단위 활동·정량 요약·시청자·동접·합산 통계

기본 내보내기는 분석용 화자 키를 유지하고 닉네임을 가명으로 바꾸며 공개 계정 ID·원문 메시지 ID를 제외합니다. 체크박스로 공개 식별 정보 포함을 선택할 수 있습니다. 채팅 원문·인용은 그대로이므로 본문에 적힌 개인정보까지 제거된다고 보장하지 않습니다. 채팅은 분석 대상 데이터이며 실행할 명령이나 지시로 취급하지 않습니다.

로그인 토큰·API 인증 정보·분석용 비밀값은 내보내지 않습니다. 진행 중인 방송을 내보내면 해당 시점의 스냅샷입니다.

## AI 실행 설정과 결과 보관

JSONL 내보내기와 앱의 AI 실행 결과는 별도로 관리합니다. 분석 요청은 `functionId`로 기능을 지정하고 앱이 개별 기능 → 그룹 → 전체 기본값 순서로 AI·CLI/API 방식·모델·추론 수준을 결정합니다. 지정한 연결을 사용할 수 없으면 이유를 표시하고 실행을 차단합니다. 실행을 시작한 뒤의 설정 변경은 진행 중 분석에 적용하지 않습니다.

`ai/settings.json`에는 연결·모델 캐시·그룹/기능별 설정을 일반 JSON으로 저장하며 API 키는 넣지 않습니다. 키는 `ai/credentials.enc`, 결과는 `ai/results.enc`에 Windows 암호화로 보관합니다. CLI 인증 정보는 각 CLI의 프로필 저장 형식을 따릅니다.

결과에는 기능 ID와 설정 출처(`assignmentSource`), 실제 AI·방식·모델·추론 수준, 요청·범위·전송 미리보기·사용량·비용·한도·실행 상태와 본문을 기록합니다. 보관 수·용량·본문 길이에 제한이 있으며 잘린 응답은 화면에서 알립니다. 결과 선택·삭제는 원본 채팅 기록과 별도입니다.

## 날짜 조회와 디스크 관리

채팅 기록은 **전체 방송·전체 날짜**로 열립니다. 방송 범위를 좁히거나 치지직·YouTube·트위치별로 조회할 수 있으며, 모든 플랫폼을 함께 볼 수도 있습니다. 각 행에는 원문의 로컬 날짜·시각을 표시합니다. 검색·시청자·채팅/후원·방송별 경과 분 필터를 지원합니다.

**날짜·용량 관리**에서 일별·월요일 기준 주별·월별로 전환합니다. 여러 항목 클릭, Shift 범위 선택, 시작/종료 날짜 지정, 전체 선택을 지원합니다. 줌을 바꿔도 선택한 실제 날짜는 유지됩니다. 창 크기에 맞춰 페이지당 항목 수를 조정해 페이지 스크롤을 만들지 않습니다.

선택 용량은 채팅·후원·시청자 프로필·동접을 포함한 암호화 원본 파일의 실제 길이입니다. 공유 통계·날짜 색인은 제외하며 파일시스템 할당 단위의 사용량과는 다릅니다. 여러 날짜를 담은 이전 버전 파일은 선택 범위에서 한 번만 합산하고 공유 용량을 표시합니다. 필요한 프로필 보존과 공유 파일 정리 때문에 실제 확보 용량은 달라질 수 있습니다.

삭제 전에 날짜와 용량을 확인하고, 기록 중인 방송의 날짜는 보호합니다. 다른 날짜와 마커를 유지하고 통계를 다시 만듭니다. 앱이 중단되어도 암호화된 삭제 작업 기록으로 다음 실행에서 정리를 완료합니다. 내보낸 파일과 외부 백업은 직접 관리합니다. 날짜별 삭제는 분석용 비밀값을 유지하고 전체 기록 삭제는 초기화합니다.

운영 워커는 1초 저장을 유지하며 최대 20,000건·8MiB 청크를 사용합니다. 동기·기존 형식의 마지막 파일 합치기는 256건·128KiB를 유지합니다. 조회 시 시퀀스 기준으로 범위를 고정해 중복을 막고 체크포인트 이후 합쳐진 기록도 복구합니다. 새 파일은 바깥쪽 Base64를 제거한 바이너리 암호화 형식이며 이전 파일도 읽습니다. 날짜·시간 색인으로 무관한 파일을 건너뛰고 바뀌지 않은 요약은 캐시합니다. 기록이 없는 동안 통계 색인을 다시 쓰지 않으며 원문 조회로 방송 메타데이터를 다시 저장하지 않습니다.

서로 다른 영상의 채팅은 원래 발생 시각의 디스크 색인으로 합쳐 하이라이트를 계산합니다. YouTube 유료 메시지의 표시 금액은 `replayDonationText`로 보존하며 정확한 통화·수치가 제공되지 않으면 후원 합계로 변환하지 않습니다. 자동 통계·하이라이트는 로컬 계산이며 외부 AI 분석과 별개입니다.
